# Передача проекта заказчику

Чек-лист. Цель — после передачи система полностью принадлежит заказчику:
**ни один ключ разработчика в ней не остаётся**, и всё продолжает работать без
его участия.

> Часть пунктов (мастер `/setup`, продакшн-сборка Docker) относится к этапу 6
> [дорожной карты](../ROADMAP.md) и появится к моменту передачи. Порядок
> действий от этого не меняется.

---

## 1. Заказчик заводит свои учётные записи

Всё делается под его аккаунтами, не под аккаунтами разработчика.

| Что | Инструкция | Результат |
|---|---|---|
| Telegram-бот | [TELEGRAM_SETUP.md](TELEGRAM_SETUP.md) | `BOT_TOKEN` |
| Проект Google Cloud | [GOOGLE_SETUP.md](GOOGLE_SETUP.md) | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` |
| OpenRouter | [OPENROUTER_SETUP.md](OPENROUTER_SETUP.md) | `OPENROUTER_API_KEY` — только если нужен AI-режим |
| VPS и домен | [INSTALL.md](INSTALL.md) | Сервер, на который указывает домен |

Ключи вписывает сам заказчик, разработчику они не нужны. Если помощь всё-таки
требуется — пусть заказчик заполнит `.env` под диктовку, а не пересылает
значения.

## 2. Новые секреты приложения

Генерируются заново, старые не переносятся:

```bash
python -c "import secrets;print(secrets.token_urlsafe(48))"   # SECRET_KEY
python -c "import secrets;print(secrets.token_urlsafe(32))"   # ENCRYPTION_KEY
```

Плюс новый `POSTGRES_PASSWORD` (он же в `DATABASE_URL`) и произвольная строка
в `BOT_WEBHOOK_SECRET`.

`ENCRYPTION_KEY` после первого подключения календарей менять уже нельзя — им
зашифрованы refresh-токены Google.

## 3. Установка на сервер заказчика

По [INSTALL.md](INSTALL.md), от начала до конца, **руками заказчика или при нём**.
Это и есть проверка документации: если инструкция не проходится без подсказок,
дорабатывается инструкция, а не заказчик.

## 4. Первичное наполнение

1. `python -m app.cli create-admin` — администратор с паролем, который знает
   только заказчик.
2. Сотрудники, услуги, расписание — по [ADMIN.md](ADMIN.md).
3. Каждый сотрудник подключает свой Google Calendar. Его Gmail должен быть
   в Test users проекта заказчика.

## 5. Приёмка

Сценарии проверяются на живой системе, а не на словах. Каждый должен пройти
целиком:

- [ ] `https://домен/health` — все поля `true`
- [ ] Вход в панель под администратором
- [ ] Запись из панели → событие появилось в Google Calendar сотрудника
- [ ] Перенос → **то же самое** событие сдвинулось, дубля нет
- [ ] Отмена → событие исчезло, время снова свободно
- [ ] Занятость, поставленная руками в Google → слот пропал из свободного времени
- [ ] Событие, подвинутое руками в Google → через 10 минут время записи в панели обновилось
- [ ] Запись клиентом в боте от начала до конца
- [ ] Перенос и отмена клиентом в разделе «Мои записи»
- [ ] Все действия видны в `/admin/audit`

## 6. Резервные копии

Настроить по [BACKUP.md](BACKUP.md) **до** запуска в работу, не после:

- [ ] Ежедневный дамп по расписанию
- [ ] Копия `.env` вне сервера
- [ ] Пробное восстановление в отдельную базу выполнено хотя бы раз

## 7. Разработчик отзывает своё

Пункт, который проще всего забыть, и он же самый важный.

- [ ] Тестовый бот удалён или отозван: @BotFather → `/revoke` (или `/deletebot`)
- [ ] Тестовый OAuth-клиент удалён в Google Cloud, тестовый проект закрыт
- [ ] Ключ OpenRouter, использовавшийся при разработке, удалён
- [ ] Тестовые данные удалены с сервера заказчика: тестовые клиенты, записи,
      демонстрационный сотрудник и услуга
- [ ] Доступ разработчика к серверу закрыт — его ключ убран из
      `~/.ssh/authorized_keys`
- [ ] Локальные копии `.env` и дампов заказчика у разработчика удалены

## 8. Репозиторий

- [ ] Репозиторий передан или скопирован в аккаунт заказчика
- [ ] Проверено, что `.env` в истории git отсутствует:

```bash
git log --all --oneline -- .env
```

Пустой вывод — всё чисто. Непустой — секреты нужно считать скомпрометированными
и перевыпустить все ключи, а не просто удалить файл: он останется в истории.

## 9. Что передаётся на словах

Один разговор на полчаса и короткий список:

- Адрес панели и учётная запись администратора.
- [ADMIN.md](ADMIN.md) — ежедневная работа.
- Где лежит `.env` и что после его правки нужен перезапуск.
- Как посмотреть, жива ли система: `/health` и `/admin/audit`.
- Что каждому новому сотруднику нужно добавить Gmail в Test users.
- Что тексты бота меняются в `app/bot/texts.py`, а фигурные скобки в них —
  подстановки, их надо сохранять.

---

## Что остаётся у заказчика

| Актив | Где |
|---|---|
| Код и история | Репозиторий в его аккаунте |
| Данные | PostgreSQL на его сервере |
| Ключи | Его `.env`, его аккаунты Telegram / Google / OpenRouter |
| Документация | Каталог `docs/` в репозитории |

Ничего из перечисленного не зависит от разработчика. Это и есть смысл слова
«под ключ».
