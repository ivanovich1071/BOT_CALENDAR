# Настройка Google Cloud: OAuth Client ID для календарей

> Выполняется ОДИН раз, под аккаунтом владельца проекта (при передаче
> заказчику — под его аккаунтом). Время: ~10 минут.

Цель — получить пару `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET`. Это ключ
приложения, а не токен доступа: access- и refresh-токены система получит сама,
когда сотрудник нажмёт «Подключить Google Calendar» и подтвердит согласие.

> API-ключ вида `AIzaSy…` здесь не работает. Он даёт доступ к публичным данным,
> а календарь сотрудника — личные данные, доступ к ним открывает только OAuth.

---

## Шаг 1. Проект

1. https://console.cloud.google.com
2. Выберите проект в списке сверху или создайте новый.

## Шаг 2. Включите Google Calendar API

☰ → **APIs & Services → Library** → найдите `Google Calendar API` → **Enable**.

## Шаг 3. Экран согласия (OAuth consent screen)

1. ☰ → **APIs & Services → OAuth consent screen**
   (в новом интерфейсе: **Google Auth Platform → Branding**).
2. User Type: **External** → **Create**.
3. Заполните: App name (это название сотрудники увидят при подключении,
   например «Запись онлайн»), User support email, Developer contact.

## Шаг 4. Тестовые пользователи

В разделе **Audience → + Add users** добавьте Gmail-адреса всех, кто будет
подключать календари. Пока приложение в статусе Testing, войти могут только они.

> Самая частая ошибка на этом шаге — `access_denied` при подключении.
> Причина почти всегда одна: адрес сотрудника не добавлен в Test users.

Публиковать приложение не обязательно: статус Testing полностью рабочий.

## Шаг 5. Создайте OAuth Client ID

1. ☰ → **APIs & Services → Credentials** (новый интерфейс: **Clients**).
2. **+ Create Credentials → OAuth client ID**.
3. Application type: **Web application**, имя — например `booking-platform`.

## Шаг 6. Authorized redirect URIs

Добавьте адреса — посимвольно, без слеша на конце:

```
http://localhost:8000/oauth/google/callback
https://ВАШ-ДОМЕН/oauth/google/callback
```

Второй адрес можно добавить позже, когда появится домен. Расхождение хотя бы
в одном символе даёт ошибку `redirect_uri_mismatch`.

Адрес должен совпадать с `GOOGLE_REDIRECT_URI` в `.env`.

## Шаг 7. Перенесите ключи в `.env`

В открывшемся окне будут Client ID и Client Secret. Впишите их в `.env`
(файл в git не попадает):

```
GOOGLE_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxx
```

Окно с секретом можно открыть заново в любой момент — секрет не теряется.
После правки `.env` перезапустите приложение: настройки читаются при старте.

## Проверка

1. `/admin/settings` — строка «Google Calendar (OAuth)» должна стать зелёной.
2. `/admin/calendars` — жёлтое предупреждение исчезает, появляется кнопка
   **Подключить Google** у каждого сотрудника.
3. Нажмите её, выберите Google-аккаунт, подтвердите доступ. После возврата
   в админку появятся email и список календарей.
4. Выберите **Рабочий календарь** — именно в него будут писаться события.
5. Создайте запись в `/admin/bookings/new` и откройте Google Calendar:
   событие должно быть на месте, в описании — `Запись #N`.

## Что происходит с доступом дальше

- Разрешения (scopes) уже заданы в коде и отдельной настройки не требуют:
  `calendar.events` — события, `calendar.readonly` — проверка занятости,
  `userinfo.email` — определить, чей это аккаунт.
- Refresh-токен шифруется (Fernet, ключ `ENCRYPTION_KEY`) и хранится в БД.
  Сотрудник его не видит, клиент-секрет ему тоже не нужен.
- Отозвать доступ сотрудник может сам: https://myaccount.google.com/permissions
- В админке отключение делается кнопкой **Отключить** — события в Google
  при этом остаются, удаляется только связь.

## Если что-то пошло не так

| Симптом | Причина |
|---|---|
| `redirect_uri_mismatch` | Адрес в Google Console ≠ `GOOGLE_REDIRECT_URI` в `.env` |
| `access_denied` | Аккаунт не добавлен в Test users (шаг 4) |
| «Ссылка подключения устарела» | С момента нажатия кнопки прошло больше 10 минут — нажмите ещё раз |
| Календари не загрузились | Кнопка **Обновить календари** на странице `/admin/calendars` |
| Событие не появилось в Google | Смотрите `/admin/audit`, действие `google.push_failed` |
