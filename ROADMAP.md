# Дорожная карта

Состояние на 9 сентября 2026. Документ описывает, что сделано, что делается
дальше и по какому признаку этап считается закрытым.

Принцип: **этап закрыт, когда сценарий проходит целиком на живых данных**, а не
когда написан код. Поэтому у каждого этапа есть строка «Признак готовности» —
это то, что можно показать заказчику, а не пункт в списке файлов.

---

## Готово

### Этап 0. Каркас · закрыт

Конфигурация через `.env` (pydantic-settings), 11 моделей SQLAlchemy, миграции
Alembic, шифрование секретов (Fernet), пароли (bcrypt), сессия админа в
HttpOnly-cookie с JWT.

### Этап 1. Админ-панель · закрыт

FastAPI + Jinja2 + HTMX. Страницы: дашборд, сотрудники, услуги, клиенты,
расписание, записи, календари, настройки, аудит. RBAC — 4 роли и 10 отдельных
прав, права можно выдавать поверх роли. Расчёт свободных слотов, перенос,
отмена. Защита от двойной брони: Redis-lock на сотрудника + проверка
пересечений в одной транзакции перед commit.

**Признак готовности:** `scripts/smoke_admin.py` проходит сквозной сценарий.

### Этап 2. Google Calendar · закрыт

OAuth 2.0 у каждого сотрудника свой, refresh-токен шифруется. Запись, перенос
и отмена правят то же самое событие (`booking.google_event_id`), дублей не
возникает. Занятость из Google убирает слоты из выдачи. Обратная синхронизация:
правки, сделанные сотрудником руками в Google, подтягиваются в БД раз в
10 минут (APScheduler внутри процесса API, Redis-lock от дублей).

Ключевое решение этапа — `app/services/booking_flow.py`: единственная точка,
через которую проходит любая запись. Появившийся позже бот не продублировал ни
одного правила.

**Признак готовности — пройден на живом календаре:** свободные слоты с учётом
занятости Google → запись создана, событие в календаре → перенос сдвинул то же
событие → событие подвинуто руками в Google → синхронизация обновила БД →
отмена удалила событие.

### Этап 3. Telegram-бот для клиента · код готов, ждёт живой проверки

aiogram 3, long polling. Диалог: услуга → специалист → дата (месячный
календарь) → время → подтверждение. «Мои записи» с переносом и отменой.
Телефон спрашивается один раз и не обязателен. Тексты вынесены в
`app/bot/texts.py` — заказчик правит их, не трогая логику.

Все операции идут через `booking_flow`, поэтому защита от двойной брони, запись
в Google и аудит работают в боте сами собой.

**Признак готовности:** живой человек проходит запись в @-боте, событие
появляется в Google Calendar сотрудника. ← **это осталось сделать**

## Дальше

### Этап 4. Напоминания · 1 день

| Что | Детали |
|---|---|
| Задача в планировщике | Каждые 5 минут: найти брони, до которых осталось 24 ч и 1 ч |
| Защита от повторов | Таблица `notifications` уже создана: уникальная пара (booking_id, kind) — строка появляется только после успешной отправки |
| Отправка | Через `Bot` из aiogram по `client.telegram_id`; клиент без Telegram молча пропускается |
| Настройка интервалов | Ключ `reminders` в `app_settings` (`{"hours_before": [24, 1]}` уже по умолчанию) + поле в `/admin/settings` |
| Отмена | Отменённая запись напоминание не получает — проверка статуса в момент отправки, а не при планировании |

**Признак готовности:** запись создана на завтра, время подкручено — напоминание
пришло один раз; повторный прогон задачи второго сообщения не шлёт.

### Этап 5. AI-режим · 2 дня

Свободный текст вместо кнопок: «хочу на стрижку в пятницу после обеда».

| Что | Детали |
|---|---|
| Клиент | `app/integrations/openrouter/` — HTTP-клиент к OpenRouter (модель по умолчанию `qwen/qwen3-max`) |
| Контракт | Модель возвращает **intent-JSON**, а не команду: `{"intent": "book", "service": "...", "date": "...", "time_preference": "afternoon"}` |
| Решение | Принимает `booking_flow`, не модель. AI не пишет в календарь и не отменяет записи — он только разбирает фразу |
| Неуверенность | Не хватает поля — бот доспрашивает кнопками, то есть падает обратно в проверенный сценарий |
| Ключ | `OPENROUTER_API_KEY` заказчика; ключ пустой — режим просто выключен, кнопочный бот работает как работал |

Каркас каталогов (`app/ai/`, `app/integrations/openrouter/`) уже заведён,
`docs/OPENROUTER_SETUP.md` написан заранее.

**Признак готовности:** три фразы разного вида приводят к правильной записи, а
четвёртая — заведомо мусорная — не создаёт ничего и получает вежливый отказ.

### Этап 6. Передача под ключ · 2–3 дня

| Что | Детали |
|---|---|
| Мастер `/setup` | Первый запуск: создать администратора, ввести ключи, проверить связь с Google и Telegram — вместо ручной правки `.env` |
| Docker | `Dockerfile` (api + bot одним образом, разные команды), `docker-compose.prod.yml`, nginx с TLS (Let's Encrypt) |
| Вебхук вместо polling | Появляется публичный HTTPS — бот переключается на вебхук, `BOT_WEBHOOK_SECRET` уже в конфиге |
| Ротация ключей | Все ключи разработчика выбрасываются, заказчик заводит свои: бот, Google Cloud, OpenRouter, `SECRET_KEY`, `ENCRYPTION_KEY` |
| Документы | `docs/TRANSFER.md` (чек-лист передачи) и `docs/BACKUP.md` уже написаны — на этом этапе сверяются с фактическим деплоем |

**Признак готовности:** на чистом VPS по `docs/INSTALL.md` поднимается рабочая
система за один проход, без обращений к разработчику.

## Что намеренно не делается

| Решение | Почему |
|---|---|
| Мультиарендность (`organization_id`) | Заказчик один. Добавляется миграцией, если понадобится второй — платить за это сложностью сейчас незачем |
| MCP Google Calendar | В Developer Preview. Прямой Calendar API закрывает все кнопочные сценарии; MCP имеет смысл как слой поверх AI, не под ним |
| Кабинет специалиста в боте | Админка это уже закрывает, а сотруднику удобнее смотреть свой Google Calendar |
| Push-уведомления Google (`events.watch`) | Нужен публичный HTTPS-домен. Опроса раз в 10 минут для записи к специалисту достаточно; `watch` добавим вместе с доменом на этапе 6 |
| Отдельный процесс планировщика | Эксплуатация соло: лишний процесс — лишняя точка отказа. APScheduler живёт внутри API, от дублей защищает Redis-lock |

## Известные шероховатости

| Что | Влияние | Что делать |
|---|---|---|
| Связь с `api.telegram.org` на машине разработки прерывистая | Старт бота иногда занимает несколько секунд | Уже обходится: `with_retry` на старте, polling переживает обрывы сам. На VPS проблемы нет |
| IPv6 к Google на машине разработки не отвечает | Без обхода запрос к Calendar API падал по таймауту 60 с | Уже обходится: `app/config/network.py` ставит IPv4 первым. Отключается через `PREFER_IPV4=false` |
| `TIMEZONE=Europe/Moscow`, календарь заказчика в `Europe/Minsk` | Смещения нет (обе +3), функционально безразлично | Поменять в `.env`, если работа идёт по минскому времени |
| Alembic на Windows может упасть с `UnicodeDecodeError` | Только на машине разработки с русской локалью | Обход: `alembic upgrade head --sql`, применить через `docker exec bc_postgres psql` |
