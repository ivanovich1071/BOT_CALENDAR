признаку этап считается закрытым. Внизу — журнал изменений по коммитам.

когда написан код. Поэтому у каждого этапа есть строка «Признак готовности» —
это то, что можно показать заказчику, а не пункт в списке файлов.

## Готово

### Этап 0. Каркас · закрыт

Конфигурация через `.env` (pydantic-settings), 11 моделей SQLAlchemy, миграции
Alembic, шифрование секретов (Fernet), пароли (bcrypt), сессия админа в
HttpOnly-cookie с JWT.

### Этап 1. Админ-панель · закрыт

FastAPI + Jinja2 + HTMX. Страницы: дашборд, сотрудники, услуги, клиенты,
расписание, записи, календари, настройки, аудит. RBAC — 4 роли и 10 отдельных
прав, права можно выдавать поверх роли. Расчёт свободных слотов, перенос,
отмена. Защита от двойной брони: Redis-lock на сотрудника + проверка
пересечений в одной транзакции перед commit.

**Признак готовности:** `scripts/smoke_admin.py` проходит сквозной сценарий.

### Этап 2. Google Calendar · закрыт

OAuth 2.0 у каждого сотрудника свой, refresh-токен шифруется. Запись, перенос
и отмена правят то же самое событие (`booking.google_event_id`), дублей не
возникает. Занятость из Google убирает слоты из выдачи. Обратная синхронизация:
правки, сделанные сотрудником руками в Google, подтягиваются в БД раз в
10 минут (APScheduler внутри процесса API, Redis-lock от дублей).

Ключевое решение этапа — `app/services/booking_flow.py`: единственная точка,
через которую проходит любая запись. Появившиеся позже бот и AI не
продублировали ни одного правила.

**Признак готовности — пройден на живом календаре:** свободные слоты с учётом
занятости Google → запись создана, событие в календаре → перенос сдвинул то же
событие → событие подвинуто руками в Google → синхронизация обновила БД →
отмена удалила событие.

### Этап 3. Telegram-бот для клиента · закрыт

aiogram 3, long polling. Диалог: услуга → специалист → дата (месячный
календарь) → время → подтверждение. «Мои записи» с переносом и отменой.
Телефон спрашивается один раз и не обязателен. Тексты вынесены в
`app/bot/texts.py` — заказчик правит их, не трогая логику.

Все операции идут через `booking_flow`, поэтому защита от двойной брони, запись
в Google и аудит работают в боте сами собой.

**Признак готовности — пройден:** 9 и 10 сентября записи #9 и #10 созданы из
Telegram живым клиентом, у обеих есть события в Google Calendar сотрудника.

### Этап 4. Напоминания · код готов, живая проверка — на сервере

| Что | Как сделано |
|---|---|
| Задача планировщика | Раз в 5 минут в процессе API, Redis-lock `scheduler:reminders` |
| Когда «пора» | Окно `start_at − h ≤ now < start_at − h + 30 мин`: шесть попыток пережить обрыв связи, но без напоминания «за сутки» за два часа до визита |
| Кому не напоминаем | Отменённым записям; записавшимся уже после момента напоминания; клиентам без Telegram |
| Повторы | Исключены: строка `notifications (booking_id, kind)` появляется только после отправки, пара уникальна |
| Сообщение | Карточка записи с кнопками «Перенести» и «Отменить» |
| Настройка | `/admin/settings`: включено или выключено, часы через запятую (1–168, до трёх значений), изменение пишется в аудит |

Тесты: окна и их границы, исключения, повторы, обрыв связи и заблокированный
бот, форма в админке.

**Признак готовности:** на сервере временно `hours_before = 1`, запись на время
через 1 ч 05 мин → напоминание пришло в течение 10 минут и не повторилось.

### Этап 5. Запись свободной фразой (AI) · разбор проверен, в Telegram — на сервере

> С 11 сентября разбор фразы заменён ИИ-консультантом с диалогом — этап 8C.
> Ниже — как был устроен первый вариант.

Клиент пишет «хочу на консультацию завтра после обеда» — бот сразу показывает
свободное время на этот день и в этом окне.

| Что | Как сделано |
|---|---|
| Модель | OpenRouter, `qwen/qwen3-max`, ответ по строгой JSON-схеме |
| Что возвращает модель | Намерение: действие, услуга, специалист, дата, окно времени — не команду |
| Даты | Модель их не вычисляет: в промпт уходит готовый календарь на 14 дней |
| Кто записывает | Обычный диалог: распознанное заполняет его поля, время клиент выбирает и подтверждает кнопками |
| Чего AI не может | Записать без подтверждения, отменить или перенести запись, обойти защиту от двойной брони |
| Отказы | Нет ключа — «пока понимаю только кнопки»; сбой или мусор — «не понял» и меню |
| Расходы | Около $0.001 за фразу; не больше 20 разборов в час на клиента; сообщение обрезается до 500 символов |
| Приватность | В модель уходят только текст и справочники — без имени, телефона и Telegram ID клиента |

**Проверено:** `scripts/ai_probe.py` на живой модели — 5 фраз из 5 разобраны
верно, включая даты («завтра», «в пятницу», «в понедельник») и окна времени,
ответ за 3–4 секунды. Путь «фраза → слоты → подтверждение → запись в базе»
закрыт тестом через диспетчер бота.

**Признак готовности:** то же самое в живом Telegram на сервере.

## Что намеренно не делается

| Решение | Почему |
|---|---|
| Мультиарендность (`organization_id`) | Заказчик один. Добавляется миграцией, если понадобится второй — платить за это сложностью сейчас незачем |
| Один сервер на несколько заказчиков | «Под ключ» — значит свой VPS у каждого. Демо-стенд тоже отдельный от личных проектов |
| MCP Google Calendar | В Developer Preview. Прямой Calendar API закрывает все сценарии; MCP имеет смысл как слой поверх AI, не под ним |
| Отмена и перенос записи текстом через AI | Ошибка разбора не должна стоить клиенту визита — только кнопкой в карточке записи |
| Кабинет специалиста в боте | Админка это уже закрывает, а сотруднику удобнее смотреть свой Google Calendar |
| Отдельный процесс планировщика | Эксплуатация соло: лишний процесс — лишняя точка отказа. APScheduler живёт внутри API, от дублей защищает Redis-lock |

## Известные шероховатости

| Что | Влияние | Что делать |
|---|---|---|
| nip.io нет в Public Suffix List | Лимит Let's Encrypt общий для всех пользователей nip.io — сертификат может не выдаться. 10.09 выдался с первого раза; при продлении риск тот же | Запасной путь — DuckDNS или свой домен |
| На сервере 1 ГБ RAM | Сборка образа и PostgreSQL рядом с двумя Python-процессами — впритык | Swap 2 ГБ создаёт `server_bootstrap.sh`, память PostgreSQL и Redis урезана в compose. Хостинг заранее кладёт `/swapfile` на 512 МБ — скрипт смотрит на размер и пересоздаёт его |
| Хостинг блокирует SSH после серии неудачных входов | Временный бан IP на порт 22 — `Connection closed` ещё до пароля; сайт при этом работает | Подключаться, когда ключ точно добавлен; при бане подождать 15 минут или сменить IP (раздача с телефона) |
| Бот с тем же токеном на машине разработки | Telegram пускает только один экземпляр — второй получит `TelegramConflictError` | Пока работает сервер, локальный бот выключен. Для разработки — отдельный тестовый бот |
| Связь с `api.telegram.org` на машине разработки прерывистая | Старт бота иногда занимает несколько секунд | Уже обходится: повторы на старте, polling переживает обрывы сам |
| IPv6 к Google на машине разработки не отвечает | Без обхода запрос к Calendar API падал по таймауту | Уже обходится: `app/config/network.py` ставит IPv4 первым. Отключается через `PREFER_IPV4=false` |
| Один Google-аккаунт подключён нескольким сотрудникам | Если у них один рабочий календарь, занятость общая: запись к одному закрывает время у всех | Создать в Google отдельный календарь каждому и выбрать его рабочим; страница «Календари» предупреждает о совпадении |
| `TIMEZONE=Europe/Moscow`, календарь заказчика в `Europe/Minsk` | Смещения нет (обе +3), функционально безразлично | Поменять в `.env`, если работа идёт по минскому времени |
| Alembic на Windows может упасть с `UnicodeDecodeError` | Только на машине разработки с русской локалью | Обход: `alembic upgrade head --sql`, применить через `docker exec bc_postgres psql`. На сервере миграции идут в Linux-контейнере |
